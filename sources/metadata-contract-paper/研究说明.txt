论文题目：From Model Metadata to Executable Interfaces: A Controlled Study of
Tensor Binding and Decoder Contracts

这次将论文主线具体化为：在生成模型接口时，结构有效性、输出索引对应的语义、
解码器前置条件是三个不同的契约。模型计算完全不变时，后两者仍可能失效。

本次新增工作
1. 预先列出官方存储域上的 8 个候选下载地址，7 个成功，1 个 404；解包后 14 次组件出现、
   13 个不同文件哈希、12 组去元数据后的计算图。共享组件不重复算新发现。
2. 11 个组件有元数据，属于 10 组计算图；2 个无元数据的组件明确记为无法检查。
3. 形成 46 个原始／对照／干预变体。官方结构校验拒绝全部 11 个条目数错误，
   但接受 8 个索引交换和 5 个标签删除；这些是人工对照，不是假装发现的新缺陷。
4. 35 个通过结构校验的变体完成 105 次 CPU 推理，所有对应输出逐字节一致。
5. 23 次隔离的 JVM 类别解码实验全部符合所检查 API 的前置条件判断。
6. 手势分类器和 EfficientNet 原版能正常解码。各删去一个标签后，生成代码和
   编译后的类字节不变，但解码失败。这两组对照不依赖 Hand 的语法修补。
7. 已实现可对单个模型运行的静态检查命令；没有来源支持的语义判断会明确放弃。

论文贡献怎样表达
可主张：一组明确的元数据消费契约、具体失效机制、与官方结构校验的实测区别、
保持模型计算不变的对照证据，以及可复核的实现和材料。
不主张：首创“设计契约”或“跨文件一致性检查”、一般缺陷检出准确率、生态缺陷
比例、Android 应用崩溃、真实图像识别精度下降、真实用户影响。

为什么比原稿更能形成论文
原稿主要依赖一个历史 Hand 样本。本稿有成功对照、失败对照、主动放弃检查的
边界和无需代码修补的编译/解码分离证据。它已经可以围绕研究问题和实验组织，
而不必让 41 例未经本次核实的 agent 评审承担研究可信度。

仍需如实披露的部分
* 两个 palm 文件虽然哈希不同，但规范化计算图相同。
* DeepLab 的生成器已有不支持非 RGB 类型的警告，不能声称完全没有工具提示。
* I（语义索引）目前只对 Hand 和 Pose 有组件级官方来源，其他组件不猜测语义。
* D（解码前置条件）针对一个具体 TensorLabel API，其 23/23 符合预期不是通用
  检测器准确率，因为规则来自同一 API 的实现。
* 语义映射由本工作流在查看来源后编写；没有独立人类评审。
* 使用 tflite-support 0.4.4，不能直接推广到所有新版 LiteRT/Android Studio 工具。
* Stalnaker 文献身份和摘要已核对，但全文下载被出版社拒绝；DARA 和 AIBOM 全文
  已获取并针对相关章节核查。现有工作比较仍不是穷尽搜索。

建议推进路线
优先按短篇／Workshop 案例研究组织，目前 PDF 是通用双栏版式，已实际渲染为 5 页。
选定具体会议后再迁移正式模板，并围绕其范围补最关键的一项证据：例如另一版本的
消费者工具比较、一个完整应用路径，或独立人工审核。不要通过堆重复模型扩大数字。
更完整的会议／期刊论文需要扩展消费者、独立评价和适用性证据。
