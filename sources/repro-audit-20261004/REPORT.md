## Confirmed problems and disposition

1. **High: E5 and the simple baseline model Java labels incorrectly.** Python
   `splitlines()` recognizes separators Java's `FileUtil` does not. On the exact
   classifier and unchanged generated source, replacing one LF with VT makes
   the old checker accept 1,000 labels while Java loads 999 and throws. Inserting
   U+2028 inside a label makes the checker reject 1,001 while Java loads 1,000
   and succeeds. Actual FileUtil/TensorLabel and Task initialization confirm both
   directions. These injected probes are separate from Android model inference.
   The new maintained checker and baseline use the real valid-UTF-8 line rules;
   malformed UTF-8 explicitly abstains. Twenty-two Java differential cases,
   three malformed-input abstentions and 71 integration checks pass, including
   unchanged judgments on all original 65 fixtures.
2. **Medium: missing evidence can receive success prose or exit zero.** The old
   standalone rebuild auditor accepts a synthetic case with zero raw observations
   and 16 UNVERIFIABLE records. Other old paths ignore a companion audit failure,
   hardcode success prose, use vacuous `all([])`, or return zero after worker
   failure. Full historical finalization has extra guards, so these findings do
   not show that the complete historical pipeline accepted missing evidence.
   New strict Android/corpus/Task readers require actual artifacts and complete
   records. Historical report templates remain preserved and should not be used
   as general validators. Executable negative probes document the failures.
3. **Medium: optimization can disable integrity assertions.** Required checks in
   old scripts use Python `assert`. A harmless invalid-input probe confirms they
   disappear under optimization. New strict helpers use explicit checks; run
   preserved scripts without `-O` or `PYTHONOPTIMIZE`. Ordinary prior executions
   are not invalidated by this finding.
4. **Paper correction required.** Line 58's library-equivalent counting wording
   is too strong for the evaluated checker, beyond the regex limitation already
   described at line 206. Retain the reproduced 65-fixture counts, disclose the
   new line-parser counterexamples, and identify the corrected implementation
   separately. The audited historical manuscript is preserved for traceability.
5. **Evidence and contribution limits remain.** E3 changes platform/runtime along
   with consumer; E2 demonstrates association changes without an independently
   artifact-tied class-order reference; Hand uses one image; E4 is purposive
   static scope checking; core E5 adds no rejection over strong comparators.
   These constrain the paper's claims and are not repaired by repeating runs.
