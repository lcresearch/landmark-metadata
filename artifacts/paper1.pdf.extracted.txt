From Model Metadata to Executable Interfaces:
A Controlled Study of Tensor Binding and Decoder Contracts
Author information to be supplied
Working research draft — October 4, 2026
Evidence-based rewrite; independent human audit and venue formatting pending
Abstract
Model metadata and its associated resources participate in
executable interfaces through both generated bindings and run￾time decoding. We study these mechanisms while holding
model computation fixed. In an EfficientNet classifier, deleting
one associated label preserves the graph, weights, embedded
metadata, generated Java, compiled code, and tested numerical
outputs, but changes an actual generated Android getter from
success to an exception after successful inference. Restoring
the labels restores success. A predetermined, count-preserving
label permutation instead completes every tested stage while
changing 999 of 1,000 exposed label strings; scores and output
positions remain unchanged. An official Task classifier rejects
the identical deletion artifact during initialization, establishing
different enforcement stages for the two configured consumers.
A secondary Hand case supplies a source-backed output-role
mismatch, yet its metadata exchange leaves the tested official
Task result unchanged. We distinguish structural acceptance,
reference-backed association agreement, and selected-decoder
compatibility, with intervention preservation checked sepa￾rately. A frozen-rule application to 15 new graph groups and
a scoped pre-flight procedure document abstentions and un￾supported paths. These controlled results establish interface
consequences and consumer boundaries, not defect prevalence,
prediction accuracy, or a general semantic validator.
1 Introduction
A model file can produce the same numerical tensor and still
expose a different result to application code. Its generated inter￾face may read an associated label file at runtime, attach those
labels to output positions, and return categories to the caller.
A resource change can therefore alter the public result even
when neither the model computation nor the generated program
changes. Establishing that consequence requires executing the
interface, rather than inspecting metadata or reproducing a
decoder expression in isolation.
The TensorFlow Lite Support schema associates output meta￾data with SubGraph.outputs in order and documents code￾generation uses for names and associated files [1]. Official
interface-generation documentation presents generated wrap￾pers as a way to replace direct buffer manipulation [2]. These
mechanisms create two distinct dependencies. Embedded out￾put metadata can change a generated getter’s binding; asso￾ciated resources can change the behavior of an unchanged
getter that loads them. Both must be distinguished from the
numerical computation represented by the model graph.
We ask: When computation is held fixed, how do changes
to output metadata or its associated resources affect an exe￾cuted interface, and where do configured consumers enforce
the relevant contracts? Our primary experiments use an Effi￾cientNet wrapper that compiles without source repair. They
establish a getter-time failure, a successful but changed label
association, and an earlier rejection by an alternative official
consumer. Hand provides a secondary, reference-backed asso￾ciation witness and a limit on the reach of that witness through
a task-specific consumer.
The principal contribution is a controlled execution study
with description controls, preserving interventions, reversals,
and stage-specific observations. A second contribution is a
comparison of enforcement boundaries in explicitly identi￾fied consumer configurations. A supporting pre-flight proce￾dure keeps structural facts, supplied-reference agreement, and
selected-decoder preconditions separate, and abstains where
evidence is insufficient. The check conditions themselves are
not new: official library and Task implementations already
enforce the observed label-count requirement. Our contribu￾tion concerns their relationship to generated interfaces and the
evidence needed to delimit a finding.
2 Contracts and Preservation
Let a model artifact comprise graph G, weights W, ordered out￾puts O = (t0,...,tn−1), embedded metadata M, and associated
files F. Generation produces interface code H. A consumer
executes the graph and interprets its outputs using H and re￾sources from the artifact. In particular, unchanged H may
load changed F during model construction and use it at output
access. Equality of computation and code does not by itself
establish equality of exposed results.
We distinguish three contract judgments, S, I, and D. They
are separate dimensions, not a sequence of certification levels.
Missing evidence for I does not prevent a justified D judgment.
P is a separate check of the experimental intervention, not a
fourth notion of model correctness.

D: compatibility with the selected decoder. We inspect

output shape be d = (d0,...,dr−1) and the loaded label list be

a = min{ j : dj > 1}. (2)
This path requires a to exist, da = |L|, and a = r − 1 for
category-list conversion. Label counting follows the library’s
treatment of blank lines. These preconditions belong to this
overload and consumer path; they are not a universal rule for
classifiers, segmentation, or detection. Dynamic signatures
and unrecognized processing require abstention; absence of
the selected getter makes D inapplicable.
P: intervention preservation. For each controlled interven￾tion, we compare all non-metadata buffers and a canonical
serialization with the TFLITE_METADATA entry and its buffer
removed. For associated-file interventions, we additionally
require unchanged embedded metadata bytes and the complete
model prefix preceding the associated ZIP archive. Generated
source, compiled code, and corresponding runtime outputs are
measured separately. Thus P supports graph/weight preser￾vation; it does not substitute for execution evidence or imply
semantic equivalence of the public interface.
3 E1: Executed Getter Failure
3.1 Artifact, controls, and execution
The primary artifact is the official version-1 float32 Efficient￾Net Lite0 classifier [4], SHA-256 prefix 6c7ab0a6e5dc. Its
float32 input is [1,224,224,3], its output is [1,1000], and
its associated label file contains 1,000 labels. Embedded im￾age normalization specifies mean 127 and standard deviation
128. Full artifact digests and exact paths are recorded in the
accompanying claim-to-evidence map.
E1 comprises four variants: the original; a one-character,
same-length description control; deletion of the final label from
labels_without_background.txt; and restoration of the
original label payload using the same deterministic archive
writer. The deletion exactly reproduces the previously pre￾served mutant. It changes the associated resource, not the
embedded metadata table. The description control does change
embedded metadata. Restoration need not reproduce the pub￾lisher’s ZIP container bytes; it must restore its associated pay￾loads and the preserved graph/metadata.
We generate with official Support 0.4.4 and compile the byte￾unmodified Java using Temurin OpenJDK 17.0.12+7, targeting
Java 8. A pinned minimal APK uses TFLite Java/native 2.13.0
and Support 0.4.4 on an Android API-30 x86_64 software em￾ulator, CPU and one interpreter thread. The build uses javac,
D8, aapt2, zipalign, and apksigner. It does not use the genera￾tor’s historical experimental/nightly Gradle configuration. No
generated-source repair is applied to EfficientNet.
An Android instrumentation consumer calls the actual public
API:
ContractModel.newInstance(...)
→ process(TensorImage)
→ Outputs.
getProbabilityAsCategoryList()
Before calling the getter, the harness observes a duplicate of
the generated output buffer without modifying it. It neither
substitutes a handwritten decoder nor treats compilation as
execution. It records structural acceptance, generation, compi￾lation/package construction, loading, input preparation, infer￾ence, and output access, including the earliest failure and its
stack trace.
Two 224-by-224 RGB inputs are fixed before inspecting
execution results: constant RGB 127 and the row-major byte
stream (37i + 17) mod 256. Both use the generated default
preprocessing. They test the interface mechanism and preser￾vation, not recognition accuracy. The experimental unit is a
component, variant, and consumer/toolchain configuration; in￾puts are repeated observations. A separately recorded replay
reuses the same environment and APKs.

condition is injected; it is not a natural defect discovered in the
original EfficientNet artifact.
4 E2: Successful Decoding With
Changed Association
E2 tests a complementary intervention that preserves the se￾lected decoder’s label-count precondition. Before inspecting
E1 Android predictions, we fix the cyclic transformation
[L0,L1,...,LC−1] 7→ [L1,...,LC−1,L0]. (3)
It preserves the filename, label count, and multiset of strings.
The four conditions are original, the same description control,
the cyclic permutation, and its inverse restoration. They use
the E1 consumer and inputs. Original/description conditions
and restored artifact bytes overlap across E1/E2; they are not
additional independent models.
Every E2 condition passes structural population, genera￾tion, compilation, packaging, loading, inference, and the actual
getter. The permutation preserves the graph, weights, embed￾ded metadata, generated source/classes/DEX, and raw output
bytes. Argmax, top-five indices, and every returned score bit
remain unchanged. Nevertheless, 999 of the 1,000 returned la￾bel strings differ from the original for each input. One position
retains its string because adjacent original entries 638 and 639
both contain “maillot”; the prescribed permutation still applies
to the complete list. The inverse restores the original decoded
lists.
For the RGB-pattern input, raw output position 904
retains score 0.23542051017284393, while its ex￾posed label changes from “window screen” to “window
shade.” For the constant input, position 649 retains score
0.001122338930144906, while “megalith” changes to
“microphone.” The Java category index field is unset by
this overload; these comparisons use returned-list positions,
checked against all raw score bits, not that unset field.
These observations establish a successful change in exposed
association relative to the original artifact. No independent
class-order reference is tied to this exact EfficientNet version,
so I abstains. The result is neither a demonstrated incorrect
class assignment nor evidence of reduced prediction accuracy.
Passing the permutation under D is an intended boundary of a
count/shape precondition, not a false negative for a semantic
detector.
Same-environment replay agrees. Its controller lost transport
after three completed variants; the last variant had no complete
recovered result. That incomplete attempt is preserved and is
not classified as consumer success or failure. Restoration was
then run separately with the same APK and parameters, yield￾ing the same result. No completed observation was overwritten
or replaced.
5 E3: Different Stages of Contract En￾forcement
We next exercise the official Task Library 0.4.4
ImageClassifier Python/C++ API on Linux, with
CPU execution and one thread. The original artifact satisfies
its documented input/output requirements, including float￾input normalization and a category output of the accepted
shape [5]. We use the exact original, description, deletion,
and permutation model bytes from E1/E2 and their saved
RGB inputs. The Android comparison rows reuse those earlier
executions rather than count them as new runs.
The Task classifier successfully initializes and classifies the
original, description, and permutation variants, returning 1,000
categories per input. The identical deletion artifact is rejected
during initialization: ValueError, “Got 1000 class(es) for out￾put index 0, expected 999 according to the label map.” Neither
inference nor decoding is reached. In contrast, the generated
Android interface loads the artifact, completes inference, and
rejects it at the getter (Table 2).
Source inspection locates distinct checks. The Python bind￾ing invokes C++ ImageClassifier::CreateFromOptions;
the release implementation validates label-map cardinality
through CheckAndSetOutputs during initialization [5]. The
generated Java path invokes TensorLabel at output access.

6 Hand: Reference Agreement and
Consumer Reach
The secondary Hand case supplies reference-backed asso￾ciation evidence not established by the classifier experi￾ments: a graph-specific output-role reference. The fo￾cal hand_landmarks_detector.tflite, SHA-256 prefix
6acda74af3fb, names output 0 handedness with shape
[1,63] and output 2 landmarks with shape [1,1]. Official
Hand integration source routes these positions to landmarks
and handedness, respectively [6]. Shape alone is not the refer￾ence.
The source-to-artifact relationship requires an ex￾plicit bridge. MediaPipe v0.10.14 resolves to commit
4cf89a70942c; its external-file declarations pin a test bundle
by digest and storage generation [7]. That bundle’s landmark
component, prefix 11c272b891e1, is not byte-identical to the
focal component. Both contain 173 buffers; only metadata
buffer 172 differs. All 172 non-metadata buffers, canonical
graph, and output order agree. This checked graph/weight
equivalence connects the official role reference to the focal
computation; it is not a claim that the source directly pins the
focal file hash.
Exchanging metadata entries 0 and 2 changes four bytes
and preserves the graph/weights. The supplied role reference
disagrees with the original and agrees after exchange. Generic
binding evidence remains separately qualified: both original
and exchanged Java historically fail raw compilation; the same
four separator-only rewrite rules change the same two lines, af￾ter which both compile. Fresh disassembly of those preserved,
repaired classes confirms handedness-to-0 and landmarks-to-2
in the original, with the associations reversed after exchange.
This audit adds no fresh Hand compilation or execution of a
repaired Android wrapper.
We also execute the actual official MediaPipe 0.10.14 CPU
HandLandmarker Task in IMAGE mode, with one requested
hand and detection, presence, and tracking thresholds of 0.5.
The four bundle conditions are original, a container-only
rewrite, the metadata exchange, and restoration. All other
component payloads are unchanged. One thumb_up.jpg in￾put is fixed before execution; its bytes match the image pinned
by the same source revision. Each condition returns one hand,
21 landmarks, and 21 world landmarks, with identical decoded
handedness and coordinate bits. Same-environment replay
agrees. These are decoded Task outputs, not internal raw model
tensors or an accuracy benchmark.
The unchanged Task result is consistent with its fixed index
routing and explicit scalar binary-handedness conversion using
hardcoded Right/Left labels. It does not imply that all metadata
is ignored: input preprocessing still obtains model/image spec￾ifications. Nor is the metadata exchange a complete repair of
the generic interface. Its category path changes from a 63-value
tensor with two labels to [1,1], which has no nonunit axis; D
remains incompatible. Coordinate normalization is a further
postprocessing concern. Reference-backed index agreement,
scalar representation, decoder suitability, and coordinate units
therefore remain distinct.

7 Supporting Scope Checks and Pre￾flight Limits
7.1 Development evidence and frozen external
application
The primary execution study builds on an earlier, preserved ex￾ploration of 11 metadata-bearing components representing 10
canonical graph groups. Its 46 original/control/mutant variants
include 11 output-metadata count reductions, all rejected by
S; eight index exchanges and five label deletions are accepted.
All 35 accepted variants retain corresponding numerical out￾puts in the recorded 105 CPU calls on three synthetic inputs.
The 23 host-JVM probes isolate the selected decoder expres￾sion and do not instantiate Android interfaces. These records
were freshly hash/array audited, not rerun or pooled with the
new Android results. They informed rule development and the
choice of a classifier whose raw wrapper and original decoder
succeed.
To examine scope beyond those inspected artifacts, we
freeze the existing checker, mutation rules, inclusion/exclusion
criteria, semantic-reference requirements, and 20 candidate
URLs in a local commit before inspecting new candidate meta￾data. Four addresses return HTTP 404 and are retained without
replacement. Sixteen downloads yield 18 component occur￾rences; excluding one previously studied component and two
prior-graph occurrences leaves 15 new canonical graph groups.
This is a purposive, same-session freeze, not third-party pre￾registration or representative sampling.
All 15 pass S; I abstains for all because no qualifying artifact￾tied reference is supplied. Eight generated wrappers compile
unchanged and seven fail. D reports four compatible category
paths, nine incompatible paths, and two inapplicable cases
(Table 3). Five of the nine incompatible paths already fail
javac; the other four carry explicit warnings that their non￾RGB output is unsupported and falls back to a numeric tensor.
No runtime execution is performed on these external originals.
This phase establishes neither a new supported end-to-end nat￾ural failure nor a prevalence estimate. The abstentions describe
the collected evidence, not a proof that semantic validation is
impossible.
7.2 A supporting pre-flight procedure
The command inspects the generated tensor and associated-file
bindings and the understood default postprocessor, then reports
separate structural, supplied-reference, decoder, preservation,
and unknown outcomes. For the E1 mutant, it reports that the
generated category getter for output 0 selects axis 1 of size
1,000 but loads 999 labels. It can place this diagnostic before
compilation, loading, and inference. It does not compile or
execute the wrapper, infer arbitrary tensor meanings, or declare
the model universally invalid.
Evaluation covers 65 byte-distinct fixtures with provenance
aliases retained: the earlier controls/mutations and no-metadata
originals, distinct E1/E2 additions, and the external originals.
They are not 65 independent models. S accepts 52, rejects the
11 count controls, and abstains for two artifacts without meta￾data. D reports 27 incompatible, eight compatible, and 14 in￾applicable fixtures; it abstains on three dynamic-signature Ges￾ture fixtures and the two without metadata. Eleven structurally
rejected fixtures do not reach D. All 65 semantic judgments
abstain because no independently supplied artifact-tied refer￾ence is provided in this evaluation. The later Hand supplied￾reference checks are separate.
The command flags the actual EfficientNet getter failure and
does not reject the four distinct artifact conditions whose An￾droid getters succeed. It accepts the count-preserving permuta￾tion under D with semantic abstention. Its dynamic-signature
policy also abstains on the seven-label Gesture mutant whose
earlier concrete-shape isolated probe failed; thus it does not
detect every previously observed failure. Outcomes on the 15
external graphs agree with the frozen rule application, which
is an implementation-consistency check, not an accuracy esti￾mate.
This procedure is a supporting implementation of scoped
checking. MetadataPopulator already catches count reductions,
Task ImageClassifier already catches label-count mismatch
during initialization, and TensorLabel already checks it at out￾put access. Moving the selected path’s precondition earlier can
improve diagnosis without constituting a new general inference
algorithm. Unknown cases and existing unsupported-output
warnings remain visible.
8 Relationship to Existing Work
Executable preconditions are established design-by-contract
practice [8]; metadata’s role in generated interfaces is also
documented by the official schema [1]. The relevant dis￾tinction here is the controlled link between artifact resources,
unchanged computation/code, actual generated-interface out￾comes, and configured enforcement stages. We do not claim to
originate the underlying label-count rule.
Stalnaker et al. study model/dataset documentation, sup￾ply chains, and licensing [9]; DARA uses model-derived ar￾chitecture features to assess naming consistency [10]. These
works preclude a broad novelty claim for comparing model con￾tent and descriptive information. The AIBOM completeness

algorithmic contribution.
9 Validity, Reproduction, and Remain￾ing Work
Causal and construct scope. E1/E2 include a working orig￾inal, a description control, a resource intervention, and a re￾versal. P, code equality, identical prescribed inputs, and raw￾output comparisons separate the label-resource effect from
changed graph computation in the tested configuration. Nu￾merical equality on two inputs is not a task-accuracy result
or a claim about every execution environment. E2 establishes
changed association, not independently established class-order
correctness. The description control supports only the tested
edit and measured outcomes.
Consumer and sampling scope. The primary evidence con￾cerns one unmodified generated classifier interface and pinned
versions. E3 changes both consumer and platform/toolchain, so
its contrast is descriptive at that configuration level. The Hand
Task result concerns one source-pinned image and selected
metadata fields. Its source interpretation and graph-equivalence
bridge remain subject to independent human review. Exter￾nal sampling is small, purposive, and drawn from the same
publisher ecosystem; static incompatibilities, seeded failures,
and natural semantic findings must not be pooled. No preci￾sion/recall, production failure, latency, security/privacy effect,
or user impact is estimated.
Toolchain and replay. The generated historical Gradle
project is not built unchanged, and no Android Studio result
is claimed. The initial APK build was followed by recovery
of additional declared dependencies and a complete rebuild
before any Android model execution; both build records are
preserved. The emulator is version 37.2.12 (build 16428233).
Its official API-30 image archive is labeled revision 11 while
its internal properties report revision 10; archive digest and
runtime fingerprint identify the exact image. Task wheel/native
hashes are archived, but their separate embedded interpreter
versions and independent source-build equivalence are not
established. Same-environment replays are not independent
researcher reproduction.
Artifacts and evidence status. The local package preserves
exact models, associated payloads, source references, con￾trols, generated Java, classes/DEX, APKs, input/output bytes,
exceptions, commands, dependency archives, and SHA-256
manifests. A companion claim-to-evidence map connects
manuscript statements to these files. This rewrite runs no
new model experiments; it reports completed extension execu￾tions and explicitly identified recovered records. The package
still depends on the two existing workspace roots and is not
yet a standalone offline distribution or durable public release.
A public artifact package, independent replay/human audit,
closer novelty comparison, and venue-specific formatting re￾main open. Unavailable historical research-agent reviews do
not supply evaluation data.
AI assistance and responsibility. AI assistance was used
for coding, experiment execution, source inspection, analysis,
and this rewrite. Additional agent checks of the manuscript are
not independent human validation. No human audit is marked
complete. Human authors must verify claims, references, ar￾tifacts, and interpretations, accept responsibility, and prepare
the venue-required disclosure. No AI system is proposed as an
author.
10 Conclusion
With graph computation and generated code held fixed, an
associated-label intervention can cause an actual generated An￾droid getter to fail after inference; a count-preserving permuta￾tion can instead succeed while changing the exposed associa￾tion. The official Task classifier enforces the tested cardinality
condition earlier, while the secondary Hand Task is insensi￾tive to the tested output-metadata exchange on its prescribed
input. These observations support separate reporting of struc￾tural acceptance, reference-backed association agreement, and
selected-consumer compatibility, with intervention preserva￾tion checked separately. They provide bounded executable evi￾dence for these distinctions and a supporting pre-flight method
with explicit abstention.
