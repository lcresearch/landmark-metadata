# Existing-report reproduction feasibility screen

Declared after manuscript commit `b24d539b7e5b5bf33de4fa74394e25944a74a84b`
and PR #23, before fresh issue retrieval. Date: 11 November 2026.

Question: which existing real integration reports provide enough identifiable
material and a relevant acceptance boundary to justify a bounded reproduction?
This is candidate selection, not execution or natural-defect confirmation.

The fixed pool is the seven reports R1–R7 in the preserved
[public-report review](../../research/20261004-significance-review/PUBLIC_REPORTS.md):
Support #770, TensorFlow #1269, MediaPipe #22, MediaPipe #195, Support #870,
Support #703 and Support #319. No new search and no substitutions. Prior
title/body exclusions remain historical; this is not a representative corpus.

Read current issue bodies/comments through the GitHub connector. Retain retrieved
responses outside Git with new identities, not as recovered October snapshots.
Inspect exact linked artifact or implementation destinations for at most three
promising candidates. Treat a landing page, redirect, login wall or HEAD success
as availability evidence only; no original-byte identity follows without a
verified body. Do not run downloaded scripts, build apps or execute models.

Rank by: closeness to the paper's acceptance question; identifiable unmodified
artifact and consumer route; explicit observed symptom; documented expected
behavior or repair; and bounded setup effort. Distinguish supported defects,
unsupported integrations, wrong asset selection and existing correct rejection.
Negative or resolved reports can supply informative comparison cases.

Select at most three, with an explicit primary/conditional priority, missing
prerequisites, minimum experiment and stopping rule. If no candidate is ready,
say so rather than manufacture a natural-case result. Stop this screen after
the seven reports and linked-material checks for the selected candidates. Do not
contact maintainers, request access, expand the search or start reproduction.

Full responses and availability observations stay outside Git. Commit concise
selection notes, source URLs/digests and this protocol. Keep the shortlist out of
the paper's experimental sample until actual reproduction has new evidence.
